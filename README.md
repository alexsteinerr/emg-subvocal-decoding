# sEMG-Based Subvocal Inner-Speech Decoding Device

## Summary

This repository contains the software and hardware components for an experimental **surface electromyography (sEMG)-based subvocal inner-speech decoding device**. The project investigates whether weak electrical activity generated by speech-related muscles can be used to decode intended language without requiring audible speech.

The system combines:

- **Non-invasive signal acquisition:** Surface EMG electrodes positioned over speech-related muscles, including facial and submandibular regions.
- **Real-time signal processing:** Filtering, artifact suppression, segmentation, and normalization of multichannel sEMG signals.
- **Neural decoding:** A deep-learning encoder that maps muscular activity to linguistic representations, enabling text prediction from subvocal signals.
- **Language generation:** A transformer-based language model that generates text conditioned on sEMG-derived features.
- **Embedded hardware:** An ESP32-S3-based acquisition device incorporating an ADS1299 analog front-end, wireless communication, and real-time signal streaming.
- **Communication interface:** A software interface for data collection, model evaluation, and visualization of decoded text.

The long-term objective is to investigate a wearable communication interface for people with speech impairments, including those associated with amyotrophic lateral sclerosis (ALS) and other neuromuscular conditions.

> **Scope:** This project focuses exclusively on sEMG-based subvocalisation. It does not use EEG or attempt to decode thoughts directly from brain activity.

## System Architecture Overview

The system follows a modular architecture connecting muscular signal acquisition, embedded processing, wireless transmission, and neural-to-text inference.

### High-Level Data Flow

1. **Signal acquisition:** Surface electrodes capture electrical activity associated with speech-related muscle activation.
2. **Analog front-end:** The ADS1299 amplifies and digitizes the biopotential signals.
3. **Embedded acquisition:** The ESP32-S3 samples the digitized signals and organizes them into data frames.
4. **Signal transmission:** The acquisition device streams sEMG data to the host computer or backend for processing.
5. **Neural decoding:** A trained sEMG encoder extracts temporal and spatial features associated with subvocal articulation.
6. **Text generation:** The decoder maps the extracted representations to candidate linguistic sequences.
7. **Prediction and feedback:** The resulting text is displayed for evaluation or further interaction.

### Key Architectural Principles

- **Non-invasive acquisition:** Uses surface electrodes rather than implanted neural interfaces.
- **Low-latency processing:** Supports continuous acquisition and streaming for future real-time communication applications.
- **Modular architecture:** Separates hardware acquisition, signal processing, model training, and text generation.
- **Reproducible experimentation:** Uses structured recordings, consistent preprocessing, and explicit dataset splits.
- **Privacy-conscious design:** Keeps signal acquisition and inference components separable, allowing deployment choices to be made according to the sensitivity of the recorded data.

## Data Collection

### sEMG Dataset

The model uses surface electromyography recordings collected using the custom recording interface and acquisition hardware.

Where the Harvard Sentences protocol is used, the recording procedure consists of:

- **720 phonetically balanced English sentences.**
- **15 recordings per sentence.**
- **10,800 recordings** for one complete pass through the protocol.

These sentences provide structured linguistic targets for supervised learning and help expose the model to a range of English phonetic patterns.

The resulting dataset depends on the recording protocol, subject, session, electrode placement, and acquisition configuration. These factors should be recorded as metadata to support reproducibility and evaluation.

### Recording Software

The desktop recording interface supports:

- Live multichannel sEMG visualization.
- Sentence selection and presentation.
- Subject and session identification.
- Repeated recordings for each target sentence.
- Storage of signal data alongside text labels and recording metadata.
- Consistent dataset organization and train/test split management.

### Signal Processing

The signal-processing pipeline prepares the acquired recordings for model training.

Typical operations include:

1. **Filtering:** High-pass and band-pass filtering to reduce baseline drift and out-of-band interference.
2. **Mains interference suppression:** Notch filtering where required by the local electrical environment.
3. **Artifact handling:** Identification and mitigation of motion artifacts and other sources of contamination.
4. **Segmentation:** Extraction of signal windows corresponding to the intended subvocal or speech-related activity.
5. **Normalization:** Application of consistent scaling procedures across recordings and channels.

Preprocessing parameters should be fitted or selected using training data only where applicable, and the same processing configuration should be applied during validation, testing, and deployment.

## Model Training

### sEMG-to-Text Architecture

The decoding pipeline transforms multichannel sEMG signals into a representation suitable for linguistic prediction.

The architecture can be organized into three principal stages:

1. **sEMG encoder:** Learns temporal and cross-channel patterns from muscular activity.
2. **Feature projection:** Maps the encoder output into the representation space expected by the language decoder.
3. **Language decoder:** Generates text conditioned on the sEMG-derived representation.

### Key Components

**1. Multichannel sEMG Encoder**

The encoder processes the time-series signals acquired from the electrode array.

Depending on the implemented model, it can use temporal convolutions, residual blocks, attention mechanisms, or other sequence-modelling layers to learn discriminative representations of muscular activity.

**2. Feature Projection**

The encoded signal representation is transformed into a sequence or set of embeddings compatible with the downstream decoder.

This interface separates the signal-specific representation learning from the language-generation component.

**3. Language Decoder**

A transformer-based language model generates text conditioned on the projected sEMG features.

The decoder may use a learned prefix or another conditioning mechanism to integrate the encoded signal into the language model. Parameter-efficient fine-tuning can be used when supported by the selected implementation.

**4. Training and Evaluation**

The training pipeline should support:

- Configurable model and optimization parameters.
- Training and validation datasets.
- Checkpoint saving and restoration.
- Loss tracking and early stopping.
- Qualitative comparisons between target sentences and predicted text.
- Quantitative evaluation using suitable text-generation metrics.

Train/test separation should prevent recordings from the same underlying trial from appearing in both sets. Subject-independent evaluation should also be considered when recordings from multiple participants are available.

## On-Device Hardware

### Hardware Architecture

The device uses a microcontroller-based acquisition system to capture sEMG signals from surface electrodes and transmit them for inference.

The acquisition chain follows this general structure:

```text
[Surface EMG Electrodes]
          |
          v
[ADS1299 Analog Front-End]
          |
        SPI
          |
          v
      [ESP32-S3]
          |
     Wi-Fi / BLE
          |
          v
 [Host Computer / Backend]
          |
          v
   [sEMG-to-Text Model]
          |
          v
    [Decoded Text]
```

### Key Hardware Components

**1. Surface EMG Electrodes**

Surface electrodes measure voltage differences associated with the activation of speech-related muscles.

Electrode placement is an important experimental variable because the recorded signals depend on the selected muscles, skin contact, electrode spacing, and movement artifacts.

The acquisition setup should document electrode positions and the reference configuration used for each recording session.

**2. ADS1299 Analog Front-End**

The ADS1299 is a multichannel, 24-bit analog-to-digital converter designed for biopotential measurements.

Its role in the acquisition chain includes:

- Amplification and digitization of low-amplitude biological signals.
- Configurable channel gain and sampling rate.
- Differential input measurements.
- SPI communication with the microcontroller.
- Support for appropriate bias and reference-electrode configurations.

The ADS1299 supports up to eight input channels. The number of channels actually used depends on the PCB design and electrode configuration.

**3. ESP32-S3 Microcontroller**

The ESP32-S3 coordinates signal acquisition and data transmission.

Its principal responsibilities include:

- Communicating with the ADS1299 over SPI.
- Reading and buffering acquired samples.
- Organizing multichannel signals into transmission frames.
- Streaming data over Wi-Fi or Bluetooth Low Energy, as implemented.
- Managing device configuration and acquisition state.

The sampling rate, buffering strategy, and wireless protocol should be configured according to the implemented firmware and the latency requirements of the decoding pipeline.

**4. Power and Wearable Integration**

The hardware can be integrated into a wearable configuration using a suitable battery, power-management circuitry, electrode connectors, and a compact PCB.

For wearable operation, the design should account for electrical isolation, safe battery charging, electrode contact, mechanical stability, and interference introduced by movement or wireless electronics.

### Firmware

The firmware is responsible for initializing the acquisition hardware and maintaining a reliable stream of sEMG samples.

Its main operations are:

1. Initialize the microcontroller and ADS1299.
2. Configure the acquisition channels and sampling parameters.
3. Acquire and buffer digitized samples.
4. Package the multichannel data into frames.
5. Transmit the frames to the receiving application.
6. Handle connection errors, buffer overflow, and acquisition interruptions.

The embedded firmware and host-side processing pipeline should use a consistent definition of channel order, sample rate, numeric representation, and frame format.

## Quickstart

The following instructions provide a high-level starting point. Exact commands and dependencies depend on the repository implementation.

### 1. Clone the Repository

```bash
git clone https://github.com/alexsteinerr/emg-subvocal-decoding
cd emg-subvocal-decoding
```

### 2. Install Dependencies

Create a Python environment and install the project's dependencies:

```bash
python -m venv .venv
```

Activate the environment and install the applicable requirements:

```bash
pip install -r requirements.txt
```

If the repository maintains separate dependency files for data collection and model training, install the relevant requirements from those directories instead.

### 3. Collect sEMG Data

Connect the acquisition hardware and launch the recording interface:

```bash
cd recording_software
python recording_software.py
```

Select the participant, session, and target sentence, then record the required repetitions.

Verify that the resulting recordings contain the expected signal channels, labels, timestamps, and metadata before starting training.

### 4. Train the Model

From the repository root, run the applicable training script:

```bash
python ml/scripts/train.py
```

Check the training configuration for the dataset location, model parameters, preprocessing settings, and checkpoint directory.

### 5. Build and Flash the Hardware

Install PlatformIO and open the `hardware/` project.

Configure the acquisition parameters and communication settings for the target board, then build and upload the firmware:

```bash
cd hardware
pio run
pio run -t upload
```

Confirm that the firmware initializes the ADS1299 and that the device produces valid multichannel samples.

### 6. Run Inference

Start the host-side inference application or backend, connect the acquisition device, and verify that the incoming signal frames match the format expected by the trained model.

Evaluate predictions against known target sentences before attempting continuous or real-time operation.

## Limitations and Future Work

Subvocal sEMG decoding remains an experimental research problem. Muscular signals vary across participants, electrode placements, sessions, and intended utterances. In particular, performance on recorded speech-related muscle activity should not automatically be interpreted as evidence of reliable decoding of purely imagined inner speech.

Future development may focus on:

- Improving generalization across sessions and participants.
- Reducing sensitivity to electrode displacement and movement artifacts.
- Developing low-latency streaming inference.
- Evaluating performance on genuinely subvocalized tasks separately from overt speech and whispered speech.
- Integrating the decoder into a lightweight wearable communication interface.
- Implementing confidence estimation and user confirmation before executing decoded commands.
